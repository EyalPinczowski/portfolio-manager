### 2.0-A money correctness (backend only)
1. `_record_flow` (`api/portfolios.py`): use the valuation's currency, not `Security.currency`. Record a **deferred flow** when an unpriced holding gets its first real price (or exclude unpriced holdings from value and flows; pick one, document it). Tests for both verified holes: (a) a holding added with no quote and no cost must not produce a +1,666 % since-start when the quote arrives; (b) AAPL with an ILS cost of 700 must not become a 7,000 USD flow.
2. Importer bodies are strict: `ParsedRow`, `ProposedChange`, `ImportRowModel`, `ImportPatch` get `allow_inf_nan=False` and `ge/le` bounds; `currency: Literal["ILS","USD"]`; `unit` must agree with `currency` (agorot ⇒ ILS); `tase_number` matches `^\d{5,9}$`; `symbol` capped and regex-checked; `name` capped, with runs of 6+ digits masked server-side; `PATCH rows` has `max_length=200`; rate-limit the PATCH route. Reject NaN/Infinity in **all** JSON bodies (one strict parser). `confirm_draft` and `match.apply_match` use the same unit/currency field (the `currency_changed` flag must compare what is stored). Tests: `quantity: 1e308`, `value: Infinity`, a 100 KB currency, a 1 KB `tase_number`, currency USD with unit ILS.
3. Matching: the index contains **verified securities plus symbols already in this user's portfolios** only. Ambiguous names (for example Hebrew "אלפבית" ⇒ GOOG or GOOGL) return candidates, never auto-accept. Tests: user A adds `PALANTIR`, user B's "Palantir" row must not match it and must not list `APPLE` from A.
4. Persist Yahoo's currency in `Security` (new column and Alembic revision) so a restart doesn't blank TASE quotes under a 429. Single-ticker retry rotation so junk alert symbols can't starve real ones.
5. Image decode: a `Semaphore(1)` around decode and a pixel budget by `w*h*bands` (reject CMYK/RGBA over ~12 MP or convert in strips). Test: three concurrent 25 MP RGBA images stay under a bounded peak (subprocess, VmHWM).
6. SQLite migrations: in `migrations/env.py`, for SQLite run `PRAGMA foreign_keys=OFF` before the batch transaction, run `PRAGMA foreign_key_check`, and turn it back on. Add a **"migrate with data"** test that runs a batch alter on `user` with rows in `portfolio` and `session` and proves nothing is lost. (If a revision is needed for the test, use a test-only revision.)

### 2.0-B auth, gate and ops (backend + `frontend/functions/api/[[path]].ts` only)
1. **Client IP.** The Pages Function sends `X-Client-IP` (from the incoming `CF-Connecting-IP`) and `X-Proxy-Auth: <shared secret>` (env `PROXY_SHARED_SECRET`). The API trusts `X-Client-IP` only when `X-Proxy-Auth` matches the configured secret (constant-time compare); otherwise it uses the peer or Render's `CF-Connecting-IP`. The app **refuses to start** when the proxy header is trusted and no secret is set. Update the Function's unit test. Tests: a spoofed `X-Client-IP` without the secret is ignored.
2. **Login backoff** keyed on **(email, IP)** with a much higher email-only threshold, and a **known-device cookie** (httpOnly, signed, set after a successful login, 90 days) that exempts that device from the email-only backoff. Test the verified lock-out scenario: 20 requests an hour must no longer lock a victim out of a known device.
3. **Turnstile.** After N failed logins for an (email, IP) the login endpoint requires a Turnstile token (`cf-turnstile-response`), verified server-side against Cloudflare's `siteverify` through a provider with a mockable verifier (settings `turnstile_site_key`, `turnstile_secret_key`, `turnstile_enabled`, default off in dev). A challenge-required error has a stable code (`turnstile_required`) so the frontend can show the widget. Tests with a mocked verifier. No network in tests.
4. **`Verdict` as a gated type**, constructible only through `LaunchGate.release()`. Harden `tests/verdict_contract.py`: scan enum values; ban `dict[str, Any]` and untyped responses on non-allowlisted routes; add the words `rating`, `outlook`, `target`, `bullish`, `bearish`, `trim`, `add`, `strong`, `opinion`, `call`, `signal`, `grade`; also cover the Telegram message builders and `Notification.body` creation paths (one function that every outgoing text passes through, and a test that fails if it contains a verdict word while the gate is closed). Prove each blind spot found in the re-review is now caught.
5. Production refuses `CORS_ORIGINS=["*"]`; an over-limit JSON body returns 413; purge expired `session` rows (scheduler job, test); cap the history `TTLCache` size. **Model ids move to config** (`gemini_model`, `groq_model`) with a startup "model exists" probe and a fallback list (the Gemini 2.5 series shuts down no earlier than 2026-10-16; Groq's Llama models may have left the free tier). The probe must be mockable and never block startup.
6. Scheduler: the leader election runs in its **own thread/executor**, not the job worker; `/api/health` exposes `leader`, `last_quotes_at`, `last_snapshot_at` (still no DB access on the hot path beyond one cheap read, cached for 10 s); an unopenable lock file logs loudly and the app starts with `scheduler: unavailable` visible in health.
7. Rollback-safe migrations: accept a "DB ahead" state for known later revisions (write the policy: expand → contract) in `docs/migrations.md`; add `compose.prod.yml` for Option B with no dev defaults, no spoofable proxy header, and docs off; pin GitHub Actions by commit SHA where you can verify the SHA offline, otherwise leave a TODO comment per action.

### 2.0-C foundations for Phase 2 (backend only)
1. **Typed `Explanation` v1** in `app/signals/base.py` (or `app/explain.py`) matching the `CLAUDE.md` shape: summary; per-signal `{name, score, weight, confidence, raw: dict[str, float|str|None]}`; chart annotations (levels, patterns, as typed items); risk rules applied; invalidation risks; sources with `as_of`; plus `version`. Replace the `dict[str, Any]` in API models with it. Stored with every scored object.
2. **Provider protocols** in `app/providers/base.py`: `FundamentalsProvider`, `NewsProvider`, `TranscriptProvider`, `FilingsProvider`, each returning typed `Field[T](value, source, as_of, missing_reason)`, with declared market coverage (`markets: frozenset[Literal["US","TASE","CRYPTO"]]`) so a US-only provider on a TASE symbol returns `missing_reason="coverage"` by design. No concrete network providers yet (those come with Phase 2 features); provide fakes for tests.
3. **LLM foundation** in `app/llm/`: an `LLMProvider` protocol; `LlmUsage` table (provider, model, day, requests, tokens, fallbacks) with an Alembic revision; a validate → retry-once → template helper (`structured_call`); a response cache keyed by the input hash; a DB-backed **token bucket** (8 RPM per provider); the **personal-data scrubber** (emails, digit runs of 6+, names of users from the `User` table, account patterns, `X-` tokens) with its own fixture corpus, **called inside the provider** so no role can bypass it. The **template path is the default** and is built and tested first; a fake provider and the Gemini and Groq adapters (config ids, no network in tests) come after.
4. **Paper-trading tables** (Alembic revision): `PaperCall` (append-only: id, created_at, user scope or global flag, symbol, side, horizon, entry, stop, targets, explanation JSON, `model_hash`, `prompt_hash`, `weights_hash`, resolved_at, outcome) and `BacktestRun` (weights_hash, period, metrics JSON, passed, created_at). Append-only enforcement (no UPDATE except resolution fields) with tests. `LaunchGate` reads them.
5. Exit-level inputs: move the README horizon table into config (`horizon_table` setting with defaults), and add a `price_is_fresh(holding)` helper (no levels on a cost or screenshot price).

### 2.0-D frontend (frontend only; after 2.0-B and 2.0-C)
Turnstile widget on the login form (loaded lazily, `turnstile_required` flow, no third-party load unless required, CSP updated for the Turnstile origin in `public/_headers`); the known-device flow needs no UI; `npm run gen:api` types; surface `fx_stale`, scheduler health and the gate state in Settings; tests (mock mode implements the new error code and endpoints).
