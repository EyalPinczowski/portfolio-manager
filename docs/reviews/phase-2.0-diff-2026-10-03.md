## Phase 2 readiness and build order
0. **Block 2.0-F before any feature:** the high rows above.
1. **Exit levels** (`scoring/exit_levels.py`): inputs `HorizonSpec` (exists), `atr` (exists), a Chandelier helper (missing), `price_is_fresh` (exists). A new append-only `StopState(holding_id, level, as_of, reason)` for "a trailing stop only moves up". Schemas `ExitLevel`/`ExitReview` carrying `Explanation`; endpoints `GET /holdings/{id}/exit-levels` and `POST /portfolios/{id}/exit-review`. Pain point: with Yahoo 429 on Render, `price_is_fresh` will often be false. Decide a "levels from the last close" policy, or add a second quote source.
2. **`UserSettings` table:** X-ray rule toggles, buy-alert filter, weekly-review time, `week_start_day`.
3. **Committee** (`app/committee/`): Scout and Chartist first (code only, `Field[T]`), then the Peer Comparator, then the LLM roles through `structured_call` with an `UntrustedText` helper and the grounding check. Split `CIOVerdict` into a gate-free `CommitteeAssessment` (score delta clamped to ±15 in code, rebuttals) and the `Verdict` from `release()`.
4. **Evals** (`backend/evals/`) with a mock LLM, alongside the committee: anonymised-ticker variants, TASE data-empty cases.
5. **PaperCall recorder plus the public track record.** The public page conflicts with "no verdicts while the gate is closed". Proposal: show only calls whose horizon has ended, delayed, read-only, global calls only, on an unauthenticated route with its own contract-test entry.
6. **GemelNet funds:** new `Fund` and `FundHolding` tables with monthly NAV and returns. Pain point: TWR and `value_portfolio` assume daily `PriceQuote` rows; funds need monthly valuation with carry-forward and a "stale by design" flag.
7. **Dividend calendar:** a `Dividend` table filled daily by a scheduled job (yfinance is blocked on data-center IPs; TASE amounts are in agorot).
8. **TradingView widget** (display only): `frontend/components/TradingViewEmbed.tsx`, rendered only after a tap, behind a feature flag off by default; prefer the iframe embed so the only CSP exception is `frame-src` for the TradingView widget origins (verify the exact origins at build time; update `lib/security-headers.ts`, `public/_headers`, `Caddyfile`; the drift test keeps them in step); map symbols as `TASE:XXX`; never read data back from the widget.
9. **Paid LLM slot** (Claude API), disabled by default: `AnthropicProvider(_HttpProvider)` in `app/llm/providers.py`; settings `anthropic_api_key`, `anthropic_model` plus fallbacks, `llm_paid_enabled=False`, `llm_paid_daily_request_cap`; `build_providers` adds it only when both flag and key are set; extend the `model_probe.Provider` literal; its own bucket and ledger row; the scrubber already runs via `BaseLLMProvider.complete`. Needs the user's approval before enabling.

## Risks for Phase 2
1. Phantom P&L from cost-priced and pending holdings will look like model alpha or losses in the track record and the weekly review.
2. Verdict leakage through Hebrew or -ing text, LLM free text, or a public track record, while the alert path itself can be stopped by the guard.
3. Free-tier LLM prompts may be used for training, and the scrubber both leaks IDs and wipes out numbers the committee needs.
4. The quota drains silently (shared bucket, no daily cap), so the "committee" quietly becomes templates.
5. One "error" outcome closes the launch gate forever.
6. Yahoo 429s on Render block fresh prices, so exit levels are unavailable most of the day.
7. Funds have monthly data, and TWR assumes daily quotes.
8. Prompt injection through news, cached and shared across users for a week.

## Recommended changes to the Phase 2 plan
1. Add **block 2.0-F** before any feature, covering the high rows; each probe becomes a regression test.
2. Replace the word-list gate with **typed outbound messages**: no free text leaves through Telegram, Notification or the review while the gate is closed; keep the word scan as defence in depth, with NFKC and Hebrew.
3. LLM layer: scrub user text only; `UntrustedText`, the grounding check, `cache_scope`, provider and model in the cache key; per-user and per-role budgets plus a daily cap; an explicit Gemini thinking budget; decide whether the free tier's training terms are acceptable, otherwise prefer OpenRouter with ZDR or the paid slot for portfolio-specific prompts.
4. Launch-gate metrics: errors counted inside the window, calls tied to the active hashes, DELETE/UPDATE triggers on both databases, no backdating.
5. Split `CIOVerdict` into an assessment and a gated `Verdict`. Define a public track-record rule (only calls whose horizon ended) before building the page.
6. Add `UserSettings` and `StopState` tables in the first Phase 2 migration (expand-only), and `Fund`/`Dividend` in the funds feature's own migration.
7. Plan a second free quote source, or a "last close" exit-level policy, before exit levels ship.
8. Pin `edgartools<6`. Discover the GemelNet resource ids at build time.
