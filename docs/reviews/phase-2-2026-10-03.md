## Security findings
Screenshot retention evidence:
- **Temp files: confirmed, and worse than documented.** Starlette spools file parts over 1 MB to disk. FastAPI parses the form **before** auth, so an *unauthenticated* 3 MB POST created a temp file and then got 401 (verified). Starlette has no size cap on file parts.
- Logs: no OCR text or image bytes are logged (by reading). If Gemini returns an invalid row, the unhandled pydantic `ValidationError` traceback includes `input_value` (stock rows only).
- DB: `HoldingsSnapshot` and `Transaction` hold only stock fields. **`ImportDraft.rows` can hold non-stock text (below).** Drafts are never deleted and are included in `/me/export`.
- OpenAPI, errors, frontend (blob URLs, storage, service worker): clean.

## Option A feasibility (512 MB / Postgres / cookies)
**Memory (measured):** interpreter 9 MB → +pandas 64 MB → +app 112 MB → +yfinance 132 MB → +genai 148 MB → with scheduler and cache 152 MB. **Idle ≈ 150 MB, so 512 MB works for steady state.** The risks are spikes: argon2 (up to 664 MB with concurrency), a tall screenshot (+200 MB) or a bomb (+800 MB), Tesseract, and the history cache.

**Postgres:** the full suite passes on PG16. Missing: Alembic (only `create_all` today), `psycopg` is not a dependency, foreign keys have no `ondelete` (manual ordered deletes), and Supabase's transaction pooler (port 6543) breaks psycopg prepared statements (use the session pooler or `prepare_threshold=None`; *verify*).

**In-process scheduler:** feasible with a single worker, if we add the startup catch-up snapshot, `misfire_grace_time`, and a DB advisory lock so a second instance never runs jobs twice. The 0.1 CPU is shared with requests.

**Cookies across sites:** a Cloudflare Pages site and an API on `*.onrender.com` are different sites. `SameSite=Lax` cookies are not sent on cross-site `fetch`, and Safari blocks third-party cookies. **Recommended: a same-origin proxy**, a Cloudflare Pages Function at `functions/api/[[path]].ts` that forwards `/api/*` to Render and passes `CF-Connecting-IP`. The cookie stays first-party, there is no CORS, and the rate limiter trusts only that header. (The alternative, `app.` and `api.` on one domain, needs a paid custom domain.)

**Terms (secondary sources; *verify*):** Render free spins down after 15 min without traffic and no explicit ban on keep-alive pings was found. Supabase pauses after 7 days without DB activity. UptimeRobot free: 50 monitors at 5-minute intervals.

## Risks for Phase 2
1. **Bad money numbers spread.** Exit levels on agorot-unnormalized or cost-priced data give stops 100× off. Fix the quote and currency bugs first.
2. **TASE coverage hole.** defeatbeta and Finnhub are US only, so most committee inputs for TASE names will have `confidence=0`. The CIO must not get confident on thin data.
3. **LLM quota volatility.** The template path will often be the real path, so test it first.
4. **512 MB plus spiky work** (committee calls, image decode, argon2) can OOM-kill the scheduler.
5. **Yahoo throttling the Render IP** can blank prices for hours. Show stale states in "Why?".
6. **Verdict leakage** without a central gate.
7. **Privacy:** a personal-data scrubber is needed before any LLM call, not only for OCR.

## Recommended changes to the Phase 2 plan
1. **Fix first:** single-ticker quote, unknown-currency/agorot fallback, flow-gap TWR, null `pnl` in the UI, fuzzy-match tightening, currency-override flag, FX staleness. Add regression tests for each.
2. **Security block (same phase):** body-size middleware and raw-body upload; pixel cap; argon2 parameters plus a semaphore; proxy-aware rate limits plus signup and upload limits; silence httpx logs; typed PATCH bodies; drop non-stock OCR lines; 24 h draft purge; security headers and no-store; clear the cache on logout; symbol validation and per-user alert caps.
3. **Launch gate first, verdicts second.**
4. **Calendars:** `exchange_calendars` with a config override, a post-close quote fetch, and a shared week-start setting.
5. **Data plan:** defeatbeta is US-only and weekly. For TASE use yfinance plus best-effort MAYA, else `confidence=0`. Finnhub for news and recommendations. EDGAR via `edgartools`.
6. **LLM layer:** a per-provider daily quota tracker, the Groq model in config, templates as a first-class path, and a personal-data scrubber before every LLM call.
7. **Option A prerequisites before deploy:** Postgres in CI plus Alembic, an in-process scheduler with an advisory lock and catch-up, the Cloudflare same-origin proxy, a slim image without Tesseract, and in-browser OCR.
8. **Contract hygiene:** generate the TypeScript types from `openapi.json`, make the backend enums `Literal`, and validate the mocks against the schema.
9. **Infra:** `uv.lock`, a CI workflow, and docker-compose.
